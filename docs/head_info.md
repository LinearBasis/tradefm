# Decision Head: таргеты и архитектура

Документ описывает варианты таргетов для каждой из трёх голов decision module,
их применимость к разным стратегиям, и финальный выбор для market making.

## Общая схема

```
Transformer (frozen) → extract_latent() → (B, d_model)
                                              │
                          ┌───────────────────┼───────────────────┐
                          ▼                   ▼                   ▼
                     Alpha (μ)           Risk (σ)          Intensity (κ)
                          │                   │                   │
                          └───────────────────┼───────────────────┘
                                              ▼
                                    A-S / GLFT формула
                                              ▼
                                     (bid, ask, sizes)
```

Три головы — общая декомпозиция торгового решения. Конкретные таргеты
и формула комбинации зависят от стратегии.

---

## Head 1: Alpha (μ) — directional signal

### Варианты таргетов

#### 1.1 Normalized mid return
```
μ[t] = (mid[t+τ] - mid[t]) / mid[t]
```
- **Что значит:** относительное изменение mid-price через τ событий
- **Подходит для:** любая стратегия (market making, directional, stat-arb)
- **Плюсы:**
  - Сопоставим между инструментами (нормировка на mid)
  - Прямо интерпретируется: "цена вырастет на X bp"
  - Естественно подставляется в A-S (reservation price) и Kelly (position sizing)
- **Минусы:**
  - На коротких горизонтах очень шумный (signal-to-noise ratio мал)
  - Не учитывает путь цены — только конечную точку

#### 1.2 Raw price change
```
μ[t] = mid[t+τ] - mid[t]
```
- **Что значит:** абсолютное изменение в рублях
- **Подходит для:** одноинструментная стратегия
- **Плюсы:** проще, нет деления
- **Минусы:** несопоставим между инструментами разной цены, одна голова не работает на все 20

#### 1.3 Sign of return (classification)
```
μ[t] = sign(mid[t+τ] - mid[t])  ∈ {-1, 0, +1}
```
- **Что значит:** только направление, без магнитуды
- **Подходит для:** directional trading с фиксированным размером позиции
- **Плюсы:** устойчивее к шуму, проще обучить
- **Минусы:** теряет информацию о величине движения, для A-S нужна магнитуда

## Head 2: Risk (σ) — оценка опасности

### Варианты таргетов

#### 2.1 Realized volatility
```
σ[t] = sqrt(Σ r[i]²)  для i ∈ [t, t+τ)
где r[i] = (mid[i+1] - mid[i]) / mid[i]
```
- **Что значит:** суммарная "дрожь" цены в окне
- **Подходит для:** любая стратегия (sizing, hedging, spread control)
- **Плюсы:**
  - Стандартная мера в microstructure литературе
  - Аддитивна по подинтервалам (можно агрегировать)
  - Статистически устойчива
- **Минусы:**
  - Измеряет общую волатильность, не отделяет "опасную" (adverse selection) от "безопасной" (noise)
  - Цена может уйти и вернуться — RV будет высокой, хотя для маркет-мейкера это не опасно

#### 2.2 Adverse selection
```
AS[t] = sign(flow[t]) * (mid[t+τ] - mid[t]) / mid[t]
где flow[t] = buy_volume[t-w:t] - sell_volume[t-w:t]
```
- **Что значит:** насколько mid-price двигается *в сторону* агрессора после текущего момента
- **Подходит для:** market making
- **Плюсы:**
  - Самая релевантная мера для маркет-мейкера: именно adverse selection определяет убытки
  - Информированный поток → высокий AS → нужен широкий спред
  - Напрямую связана с P&L маркет-мейкера
- **Минусы:**
  - Зависит от определения flow (окно w, buy vs sell classification)
  - Шумнее realized vol
  - Менее стандартная, сложнее сравнивать с литературой

#### 2.3 Max adverse excursion (MAE)
```
MAE[t] = max(|mid[i] - mid[t]|) / mid[t]  для i ∈ [t, t+τ]
```
- **Что значит:** максимальное отклонение mid от текущей в окне — worst case
- **Подходит для:** market making, risk management
- **Плюсы:**
  - Ловит хвостовые риски: если цена ушла на 20bp и вернулась, RV занижает опасность, MAE — нет
  - Для маркет-мейкера важно именно peak deviation: мы рискуем на момент максимального отклонения
- **Минусы:**
  - Нестабильна (одно экстремальное движение определяет всё значение)
  - Не аддитивна по подинтервалам
  - Чувствительна к выбросам (microstructure noise, ошибочные trades)

#### 2.4 Order flow imbalance (OFI)
```
OFI[t] = (buy_volume - sell_volume) / total_volume  за [t-w, t]
```
- **Что значит:** дисбаланс потока на момент t
- **Подходит для:** market making, short-term alpha
- **Плюсы:**
  - Leading indicator (из прошлого, не из будущего)
  - Предсказывает adverse selection
- **Минусы:**
  - Не таргет для головы, а скорее входная фича или часть alpha
  - Не имеет прямого отображения в A-S формулу как σ

## Head 3: Intensity (κ) — активность рынка

### Варианты таргетов

#### 3.1 Trade count / sec
```
κ[t] = count(ACTION == 2 в [t, t+τ]) / Δt_seconds
```
- **Что значит:** частота сделок
- **Подходит для:** общая оценка ликвидности
- **Плюсы:** просто считать, интуитивно понятно
- **Минусы:**
  - Игнорирует размер: 1 сделка на 10000 лотов и 100 сделок по 1 лоту — одинаковые по count, но принципиально разные по risk и execution
  - Плохо сопоставим между инструментами

#### 3.2 Volume / sec
```
κ[t] = Σ volume(trades в [t, t+τ]) / Δt_seconds
```
- **Что значит:** объём торгов в единицу времени
- **Подходит для:** market making, execution
- **Плюсы:**
  - Учитывает размер сделок
  - Inventory-relevant: мы рискуем в объёме, не в количестве
  - Одна крупная сделка может забрать всю позицию — volume это ловит
- **Минусы:**
  - Несопоставим между инструментами (SBER — миллионы лотов, мелкие бумаги — тысячи)

#### 3.3 Normalized volume / sec (относительно ADV)
```
κ[t] = (volume за [t, t+τ]) / (daily_volume * Δt / session_length)
```
- **Что значит:** текущая активность относительно типичной для этого инструмента
- **Подходит для:** мультиинструментный market making
- **Плюсы:**
  - κ > 1 = активнее обычного, κ < 1 = тише обычного
  - Сопоставим между инструментами
  - Одна голова работает на все 20 инструментов
- **Минусы:**
  - Зависит от оценки daily_volume (может быть неточной для первых часов дня)
  - Дополнительная зависимость от daily_volume feature из pipeline

#### 3.4 Notional turnover / sec
```
κ[t] = Σ (volume * price) / Δt_seconds
```
- **Что значит:** денежный оборот в единицу времени
- **Подходит для:** кросс-инструментное сравнение, portfolio-level risk
- **Плюсы:** естественная нормализация через цену
- **Минусы:** для нашей задачи избыточно — normalized volume уже решает проблему сопоставимости

## Финальный выбор для market making

### Alpha: normalized mid return (1.1)
```
μ[t] = (mid[t+τ] - mid[t]) / mid[t]
Loss: Huber
Output: Linear (без активации, может быть отрицательным)
```
Единственный разумный вариант для A-S. Нужна и магнитуда, и знак. Нормировка
обязательна для мультиинструментной головы.

### Risk: realized volatility (2.1) + adverse selection (2.2) для сравнения
```
Основной: σ[t] = sqrt(Σ r[i]²)
Loss: MSE(log σ_pred, log σ_target)
Output: softplus (> 0)
```
Начинаем с realized vol как с надёжного базового таргета. Параллельно
реализуем adverse selection и сравниваем — если AS лучше коррелирует с
PnL маркет-мейкера на backtesting, переключаемся на него. Для диплома
это хороший ablation study.

### Intensity: normalized volume / sec (3.3)
```
κ[t] = (volume за [t, t+τ]) / (daily_volume * Δt / session_length)
Loss: MSE(log κ_pred, log κ_target)
Output: softplus (> 0)
```
Normalized volume — лучший баланс между информативностью и сопоставимостью
между инструментами. daily_volume у нас уже есть в pipeline (compute_daily_volume).

### Общие параметры
- **Горизонт τ:** 512 событий (~3 сек при 170 ev/sec), единый для всех трёх голов
- **Backbone:** frozen transformer latent (d_model=128)
- **Архитектура голов:** Linear(128, 1) — linear probe для начала

### Формула комбинации (A-S)
```
reservation_price = mid + μ − γ * q * σ² * τ
half_spread = (1/γ) * ln(1 + γ/κ)
bid = reservation_price − half_spread
ask = reservation_price + half_spread
```
γ (risk aversion) — гиперпараметр, тюнится по Sharpe на backtesting.
